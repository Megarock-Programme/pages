Connecting a source to Data Hub

Data Hub reads your database with the user you give it. Give it a user that can only read: Megabots also opens every session read-only and refuses write statements, but the database user is the guarantee the rest only backs up.

1. Create a read-only user

PostgreSQL / Aurora PostgreSQL

CREATE ROLE megabots_reader LOGIN PASSWORD '<strong-password>';
ALTER ROLE megabots_reader SET default_transaction_read_only = on;
GRANT CONNECT ON DATABASE <database> TO megabots_reader;
-- Repeat per schema the assistant should see:
GRANT USAGE ON SCHEMA <schema> TO megabots_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA <schema> TO megabots_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA <schema> GRANT SELECT ON TABLES TO megabots_reader;

MySQL / MariaDB / Aurora MySQL

CREATE USER 'megabots_reader'@'%' IDENTIFIED BY '<strong-password>' REQUIRE SSL;
GRANT SELECT, SHOW VIEW ON <database>.* TO 'megabots_reader'@'%';

Redshift

CREATE USER megabots_reader PASSWORD '<Strong-password1>';
GRANT USAGE ON SCHEMA <schema> TO megabots_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA <schema> TO megabots_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA <schema> GRANT SELECT ON TABLES TO megabots_reader;

Table and column comments (COMMENT ON ...) and foreign keys are read too: they become the descriptions and relationships the assistant uses to write correct queries. Add them where you can, or write notes in Data Hub after connecting.

2. Let Megabots reach it

Megabots connects from one public IP, its NAT gateway. Find it in the Megabots account:

aws ec2 describe-nat-gateways --filter Name=state,Values=available \
  --query "NatGateways[].NatGatewayAddresses[0].PublicIp" --output text
  • Public endpoint: allow that IP on the database port (security group, firewall, or pg_hba.conf), nothing wider. TLS is required by default (sslmode=require).
  • Private database: use an SSH bastion that the IP can reach. In the connect form open Advanced, turn on SSH bastion, and give its host, user and private key. Hosts that resolve to private addresses are refused unless they go through a bastion.
  • A database that pauses when idle (Aurora Serverless) takes up to ~15 s to answer the first connection. Test connection waits for it.

3. Athena

The data must be in this deployment's megabots-database-<account> bucket, with its tables in a Glue database. In the form give the region, the Glue database and the workgroup (primary unless you made one). Query results go to Megabots' own Athena results bucket.

Data in another AWS account is not supported yet.

4. Connect and choose who reads it

Data Hub → Connect source, paste the URL, Test connection, then under Who can read it? pick the roles. The default is nobody but admins. Use the Console tab to run a query as a role and see exactly what the assistant would get.
