Connecting a source to Data Hub

Data Hub reads your database with the user you give it. Give it a user that can only read: Megabots also opens every session read-only and refuses write statements, but the database user is the guarantee the rest only backs up.

1. Create a read-only user

PostgreSQL / Aurora PostgreSQL

CREATE ROLE megabots_reader LOGIN PASSWORD '<strong-password>';
ALTER ROLE megabots_reader SET default_transaction_read_only = on;
GRANT CONNECT ON DATABASE <database> TO megabots_reader;
-- Repeat per schema the assistant should see:
GRANT USAGE ON SCHEMA <schema> TO megabots_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA <schema> TO megabots_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA <schema> GRANT SELECT ON TABLES TO megabots_reader;

MySQL / MariaDB / Aurora MySQL

CREATE USER 'megabots_reader'@'%' IDENTIFIED BY '<strong-password>' REQUIRE SSL;
GRANT SELECT, SHOW VIEW ON <database>.* TO 'megabots_reader'@'%';

Redshift

CREATE USER megabots_reader PASSWORD '<Strong-password1>';
GRANT USAGE ON SCHEMA <schema> TO megabots_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA <schema> TO megabots_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA <schema> GRANT SELECT ON TABLES TO megabots_reader;

Table and column comments (COMMENT ON ...) and foreign keys are read too: they become the descriptions and relationships the assistant uses to write correct queries. Add them where you can, or write notes in Data Hub after connecting.

2. Let Megabots reach it

Megabots connects from one public IP, its NAT gateway. Find it in the Megabots account:

aws ec2 describe-nat-gateways --filter Name=state,Values=available \
  --query "NatGateways[].NatGatewayAddresses[0].PublicIp" --output text
  • Public endpoint: allow that IP on the database port (security group, firewall, or pg_hba.conf), nothing wider. TLS is required by default (sslmode=require).
  • Private database: use an SSH bastion that the IP can reach. In the connect form open Advanced, turn on SSH bastion, and give its host, user and private key. Hosts that resolve to private addresses are refused unless they go through a bastion.
  • A database that pauses when idle (Aurora Serverless) takes up to ~15 s to answer the first connection. Test connection waits for it.

A connection that times out usually means the firewall is dropping the request, not that the database is slow. Check the allow-list first.

3. Athena

The data must be in this deployment's megabots-database-<account> bucket, with its tables in a Glue database. In the form give the region, the Glue database and the workgroup (primary unless you made one). Query results go to Megabots' own Athena results bucket.

Data in another AWS account is not supported yet.

4. BigQuery

One source is one dataset. Megabots authenticates with a service account key, so no IP allow-list is needed.

  1. In the Google Cloud console open IAM & Admin → Service accounts and create one, for example megabots-reader.
  2. Grant it BigQuery Job User on the project (it runs the queries), and BigQuery Data Viewer on the dataset only (BigQuery → dataset → Sharing → Permissions). Do not grant Data Viewer on the whole project.
  3. Open the service account, Keys → Add key → Create new key → JSON, and download it.
  4. In the connect form give the project ID, the dataset ID, and paste the whole JSON file as the service account key.

Each query is capped at 10 GB scanned. Table and column descriptions set in BigQuery are read into the catalog.

5. ClickHouse

Connect by URL on the HTTPS interface: clickhouse://user:password@host:8443/database. Add ?sslmode=disable for a plain-HTTP server on port 8123. Megabots opens every session with readonly = 2, which refuses writes and DDL server-side. 

CREATE USER megabots_reader IDENTIFIED BY '<strong-password>' SETTINGS readonly = 2;
GRANT SELECT ON <database>.* TO megabots_reader;

On ClickHouse Cloud, add the Megabots NAT IP (step 2) to the service's IP access list.

6. Snowflake

Megabots signs in with a key pair, so no password is stored. Snowflake has no read-only session mode: the role's grants are the guarantee, so grant SELECT and nothing else.

  1. Generate an unencrypted PKCS#8 key pair: 
    openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out megabots_key.p8 -nocrypt
openssl rsa -in megabots_key.p8 -pubout -out megabots_key.pub
  2. Create the role and user, and set the public key (paste the .pub contents without the BEGIN/END lines): 
    CREATE ROLE megabots_reader;
GRANT USAGE ON WAREHOUSE <warehouse> TO ROLE megabots_reader;
GRANT USAGE ON DATABASE <database> TO ROLE megabots_reader;
GRANT USAGE ON ALL SCHEMAS IN DATABASE <database> TO ROLE megabots_reader;
GRANT SELECT ON ALL TABLES IN DATABASE <database> TO ROLE megabots_reader;
GRANT SELECT ON FUTURE TABLES IN DATABASE <database> TO ROLE megabots_reader;
CREATE USER MEGABOTS_READER DEFAULT_ROLE = megabots_reader DEFAULT_WAREHOUSE = <warehouse>
  RSA_PUBLIC_KEY = 'MIIBIjANBgkq...';
GRANT ROLE megabots_reader TO USER MEGABOTS_READER;
  3. In the connect form give the account as orgname-accountname (Snowsight → account selector → View account details), the user, the contents of megabots_key.p8, and the database. Schema and warehouse are optional.

Primary and foreign keys are informational in Snowflake, but Megabots reads them for joins.

7. Databricks

Megabots connects to a SQL warehouse with an access token. Unity Catalog is required (hive_metastore has no information_schema to discover from). There is no read-only session mode: grant SELECT and nothing else.

  1. Create a service principal (Settings → Identity and access) and generate a token for it, or use a personal access token (User settings → Developer).
  2. Grant it read access to the catalog: 
    GRANT USE CATALOG ON CATALOG <catalog> TO `<principal>`;
GRANT USE SCHEMA, SELECT ON CATALOG <catalog> TO `<principal>`;
    and Can use on the SQL warehouse.
  3. Copy the Server hostname and HTTP path from the warehouse's Connection details tab into the form, with the token and the catalog name.

A stopped warehouse starts on the first query; expect the first Test to take up to a minute.

8. Connect and choose who reads it

Data Hub → Connect source, paste the URL, Test connection, then under Who can read it? pick the roles. The default is nobody but admins. Use the Console tab to run a query as a role and see exactly what the assistant would get.
